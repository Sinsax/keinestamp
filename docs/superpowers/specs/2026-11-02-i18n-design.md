# 多语言（i18n）设计方案 — 统一 catalog

> 状态：**待确认** · 日期：2026-11-02 · 代码基线：Keinestamp v0.5.1
> 决策来源：用户确认「统一 catalog」「zh-CN + en-US」「跟随系统语言」「网页端全英文」「提交内容不翻译」「配色暂不做」

## 1. 目标与范围

| 项 | 决策 |
|---|---|
| 语言 | `zh-CN`（默认）+ `en-US` |
| 语言选择 | **跟随系统**（默认）/ 简体中文 / English 三选一 |
| CLI | **跟随系统**（与 GUI 同一优先级链，默认即跟随）；脚本确定性用 `KEINESTAMP_LOCALE` 覆盖 |
| Catalog | **全仓唯一一份**，前端与 Rust 共用同一份 JSON，不写两套 |
| 网页端 | **固定英文**，不做访客切换、不做项目级语言配置 |
| 不翻译 | 项目名、流程名、标签名、文件名、提交信息、Lore/Blender 原始输出（数据，不是 UI） |

### 覆盖的四个输出面

1. 桌面 GUI（`frontend/src`，Svelte 5）— 跟随设置
2. 生成的静态网页（`src/html_gen.rs`）— 固定英文
3. 服务器页面（`src/serve.rs`：落地页 / 登录页 / HTTP 错误）— 固定英文
4. CLI 与后端错误（`src/main.rs`、`lore_backend.rs` 等）— 同一优先级链，默认跟随系统

## 3. 架构

### 3.1 唯一 catalog

```
i18n/
  zh-CN.json      ← 唯一真源（人工维护）
  en-US.json      ← 键集必须与 zh-CN 完全相同
  README.md       ← 命名规范、复数规则、web.* 例外说明
```

嵌套 JSON + 点号路径查找（加载时展平一次）：

```json
{
  "common": { "save": "保存", "cancel": "取消" },
  "gui": {
    "actionbar": { "record": "记录", "rollback": "恢复" },
    "entry": { "files": "{n} 个文件" }
  },
  "cli": { "record": { "committed": "已提交 {hash} — {msg}" } },
  "err": { "lore": { "address_not_found": "数据已不在本地存储：…" } },
  "web": { "timeline": { "title": "Progress Timeline" }, "empty": "No records yet" }
}
```

- **键命名**：`surface.area.item`，surface ∈ `common|gui|cli|err|web`。
- **占位符**：`{name}`，运行时替换；`{n}` 用于数量。
- **复数**：`key.one` / `key.other`（中文两键写同样的文本），英文取 `other`（`n != 1` 时）。
- **`web.*` 例外**：只存在于 `en-US.json`（产品决策=网页恒英文），一致性测试对此前缀豁免。

### 3.2 Rust 侧：`src/i18n.rs`（单文件，约 150 行）

```rust
pub enum Locale { ZhCn, EnUs }
pub enum LocalePref { System, ZhCn, EnUs }   // 对应 AppConfig.locale = "system" | "zh-CN" | "en-US"

static LOCALE: AtomicU8 = AtomicU8::new(0);  // 0 = 未初始化 → 解析后缓存；1/2 = ZhCn/EnUs
static CATALOG: OnceLock<HashMap<Locale, HashMap<String, String>>>;

fn catalog() -> &'static …            // include_str!("../i18n/zh-CN.json") + 展平
pub fn system_locale() -> Locale      // sys-locale → 前缀 "zh" ⇒ ZhCn，其余 ⇒ EnUs
pub fn pref() -> LocalePref
pub fn locale() -> Locale             // KEINESTAMP_LOCALE env > pref(非 system) > system_locale()
pub fn set_locale(l: Locale)          // GUI 切换语言时改写进程内缓存
pub fn t(key: &str) -> String         // 当前 locale；缺失 → debug 显示 ⟦key⟧，release 回落 zh-CN
pub fn tf(key: &str, args: &[(&str, &str)]) -> String
pub fn t_for(locale: Locale, key: &str) -> String   // 网页固定英文用
pub fn render(tpl: &str, locale: Locale) -> String  // 替换 {{k:web.x}} 占位，供 html_gen/serve
```

**系统语言检测**：新增依赖 `sys-locale = "0.3"`（Windows `GetUserDefaultLocaleName` / macOS `CFLocale` / Linux `LANG`），外面包一层 `system_locale()`，未来要换实现只改这一个函数。**不做**运行中监听系统语言变化 —— 切换系统语言后重启生效，UI 上注明。

### 3.3 前端：`frontend/src/lib/i18n/`

```
frontend/src/lib/i18n/
  index.svelte.ts   ← $state locale、t()/tn()、setLocale()、插值
  keys.ts           ← 从 JSON 推导的字面量联合类型
```

```ts
import zhCN from '../../../../i18n/zh-CN.json'   // 同一份文件，非拷贝

type LeafPaths<T, P extends string = ''> = { … }   // 递归展开成 'gui.entry.files' 这样的联合
export type Key = LeafPaths<typeof zhCN>

let current = $state<Locale>('zh-CN')
export function t(key: Key, params?: Record<string, string | number>): string
export function tn(key: Key, n: number, params?): string   // 自动选 .one/.other
export function setLocale(l: Locale): void                 // 初始与切换都由 Rust 决定
```

- **类型安全**：key 是联合字面量，写错 `npm run check` 直接报错；`en-US.json` 缺键由 cargo 测试兜住。
- **响应式**：`t()` 内读取 `$state`，切换语言时所有使用点自动重渲染，无刷新。
- **文本外的一切不变**：不改 DOM 结构，只换文案。

### 3.4 取值优先级

```
KEINESTAMP_LOCALE (env, 显式覆盖，测试用)
  └→ AppConfig.locale（"system" | "zh-CN" | "en-US"）
       └→ system_locale()
            └→ zh-CN（兜底）
```

`AppConfig` 只加一个字段（`#[serde(default)]`，旧配置向后兼容）：

```toml
# 省略 = 跟随系统
locale = "system"     # 或 "zh-CN" / "en-US"
```

新增 Tauri 命令：`get_locale_pref` / `set_locale_pref` / `get_effective_locale`（返回 `{pref, tag, systemTag}`，供设置页显示"跟随系统（当前：English）"）。

**CLI 行为（跟随系统）**：`keinestamp` 是独立进程，启动时走完全相同的链路 —— `KEINESTAMP_LOCALE` → `AppConfig.locale` → `sys-locale` 系统探测 → `zh-CN`。

- 默认（`app-config.toml` 无 `locale` 字段或为 `system`）→ **CLI 输出跟随操作系统语言**。
- 若用户在 GUI 里固定选了语言 → CLI 跟随该选择（同一份配置，行为可预期，不会两套偏好打架）。
- 脚本/CI 要确定性 → `KEINESTAMP_LOCALE=en-US keinestamp log`。
- `keinestamp config --set locale=system|zh-CN|en-US` 可改同一份偏好。

**clap 的边界（必须如实说明）**：我们自己的文案（子命令 `about`、`--help` 里的参数说明、所有 `println!` 输出）可本地化；但 clap **自动生成的骨架**（`Usage:`、`Arguments:`、参数报错如 "unexpected argument"）是库内固定英文，本期不做逐错误定制。实现方式：`Cli::command()` 构建后按 key 打补丁（`about`/`help`），再用 `from_arg_matches` 解析，不改 derive 结构。

### 3.5 网页端固定英文

- `html_gen.rs` 模板里的中文 → `{{k:web.*}}` 占位，生成时用 `i18n::render(tpl, Locale::EnUs)` 替换；`<html lang>` 写死 `en`。
- 网页文案写进 `en-US.json` 的 `web.*`（`zh-CN.json` 不含）→ 将来要加中文网页，只需补 `zh` 的 `web.*` + 一个渲染参数，模板不用再动。
- `serve.rs` 的落地页 / 登录页 / HTTP 错误同上。
- 3D 预览、日历等纯数据区域不涉及。

### 3.6 语言切换的运行时行为

| 位置 | 行为 |
|---|---|
| 桌面 UI 文案 | 即时生效（`$state` 驱动） |
| 后端返回的字符串（错误、状态、进度事件） | 通过 `set_locale` 同步进程内缓存 → **切换后自动刷新一次当前视图数据**（status、log、timeline），避免旧语言残留 |
| 托盘菜单（`src-tauri/src/lib.rs:1763-1769` 打开/退出/tooltip） | 切换时重建 `Menu`；若重建成本高于预期则退化为「重启后生效」并在 UI 注明 |
| 已生成的网页 | 与本设置无关（恒英文） |
| 窗口标题 | 已是 `Keinestamp`，无需改 |

## 4. 硬性约束（可执行）

1. **键集一致**：`cargo test` 断言 `zh-CN` 与 `en-US` 展平后的键集完全相同（`web.` 前缀豁免）。→ 不可能出现半中半英。
2. **键存在性**：单测扫描 `src/**/*.rs` 中的 `t("…")` / `tf("…")` 字面量，断言每个 key 都在 catalog 里。→ 防拼写错误与漏改。
3. **前端类型**：`npm run check` 保证 TS 侧 key 合法。
4. **测试确定性**：`tests/cli_tests.rs` 的 `run()` 固定 `KEINESTAMP_LOCALE=zh-CN` → 现有 55 行中文断言全部继续有效。
5. **`index.html` 的 `<html lang="zh-CN">`** 改为默认值 + 运行时由 `document.documentElement.lang` 覆盖。

## 5. 已知边界

- 英文文案平均长 20–40%：`ActionBar`、`TitleBar`、`StatusBar`、`EntryList` 卡片、`ProjectTabs`、`Remote` 表格、`SettingsDialog` 为重点回归对象（`min-width:0` + `text-overflow` + `nowrap`）。
- 日期：`timeline.json` 存 ISO 8601，网页直接 `split('T')`（语言无关）；桌面端统一走 `Intl.DateTimeFormat(locale)`。
- 中英混排（项目名/标签是中文，UI 是英文）属正常现象，不做转写。
- 系统语言变化需重启生效（不监听）。
