# 多语言（i18n）实施计划 — 统一 catalog

> 方案见 [design](../specs/2026-11-02-i18n-design.md)
> **状态：已完成**（2026-11-02）。实施中的一处方案调整见文末「实施记录」。

## 风险与对策

| # | 风险 | 对策 |
|---|---|---|
| 1 | 897 串体量大，容易半途而废 | 严格分批，每批独立可发布；catalog 缺键由测试立刻暴露 |
| 2 | **Vite 跨根目录导入被拦**（`i18n/` 在 `frontend/` 之外） | P0 先验通；不行则把 catalog 移到 `frontend/src/lib/i18n/catalog/`，Rust 侧 `include_str!` 反向引用，两行改动 |
| 3 | 现有 55 行中文断言被打挂 | `run()` 固定 `KEINESTAMP_LOCALE=zh-CN`，一处改动覆盖全部 |
| 4 | 英文文案撑破固定宽度布局 | `min-width:0`+`text-overflow`+`nowrap`；8 个高风险组件逐屏回归 |
| 5 | 切语言后旧数据仍是旧语言 | 切换后强制刷新 status/log/timeline 一次；托盘菜单重建 |
| 6 | 英文质量（非母语直译感） | 文案集中一处，便于统一校对；先自校一轮再定稿 |
| 7 | Rust 侧 key 拼写错误无编译期保护 | 单测扫描源码字面量（P0.12） |
| 8 | 系统语言识别在个别环境不准（如精简系统） | 设置页明确显示"跟随系统（当前：X）"，用户可手动覆盖 |
| 9 | 新增依赖 `sys-locale` | 只用于 `system_locale()` 一个函数，隔离后随时可替换为手写实现 |

---

## 已确认决策（2026-11-02）

1. **统一 catalog**：仓库根 `i18n/` 一份 JSON，前端与 Rust 共用。
2. **语言**：`zh-CN` + `en-US`；默认**跟随系统**，可手动固定。
3. **托盘菜单**：切语言后**立即重建**，不重启。
4. **网页端**：**全部英文**（含空态、错误提示、登录页），仅用户数据原样。
5. **CLI**：与 GUI 同一优先级链，**默认跟随系统语言**；`KEINESTAMP_LOCALE` 供脚本覆盖。
6. **不翻译**：项目名、流程名、标签名、文件名、提交信息。
7. **配色自定义**：本期不做（调研结论归档在设计文档附录 A）。

## 实施记录（2026-11-02）

### 与计划的差异

1. **P3 网页端没有走 catalog 的 `web.*` 占位符**，而是把页面文案直接写成英文。
   理由：网页按产品决策恒为英文，`web.*` 只会存在单一语言，占位符+`render()` 只增加间接层；
   且 `serve.rs` 的页面是带 `{{}}` CSS 转义的 `format!` 模板，再叠加一层占位替换风险更高。
   catalog 的 `web.` 前缀保留给将来真要双语的场景（一致性测试仍然豁免该前缀）。
2. **系统语言探测零依赖**：没有引入 `sys-locale`，而是 `unsafe extern "system"` 直接声明
   kernel32 的 `GetUserDefaultLocaleName`，Unix 走 `LC_ALL/LC_MESSAGES/LANG`。
3. **额外引入结构化错误码**（计划外但必需）：`[code:xxx]消息`，替换了 4 处
   `msg.includes('中文')` 的控制流判断；`statusParse` 也改为纯结构解析。

### 实际改动规模

- catalog：`gui.*` 约 380 键、`cli.*` 约 90 键、`err.*` 约 120 键（含两语言）
- Rust：`src/i18n.rs`（约 560 行）、`src/main.rs`（clap 本地化 + 全部输出）、
  `lore_project.rs`、`lore_backend.rs`、`blender_download.rs`、`serve.rs`、`html_gen.rs`、
  `about.rs`、`push.rs`、`config.rs`、`main_helpers.rs`、`tag_groups.rs`、`timeline.rs`、
  `process_util.rs`、`init.rs`、`src-tauri/src/lib.rs`
- 前端：全部 21 个组件/模块 + 新增 `lib/i18n/`、`lib/errors.ts`

### 验收证据

- `cargo test`：250 lib + 12 integration + doctest 全绿
- `cd frontend && npm run check`：0 errors / 0 warnings
- `npm run build`、`cargo build`、`cd src-tauri && cargo build`：通过
- CLI 双语冒烟：`--help`、无参、`config` 输出均正确切换
- 生成网页与登录页：零非英文 UI 文案（用户数据除外）
